# Meta Loop

The Meta Loop improves the Product Loop only from recurring evidence.

## Entry criteria

Open a Meta Loop run only when at least one is true:

- the same failure appears in 3 or more Product Loop runs
- review routinely discovers the same avoidable defect class
- loop overhead blocks small valuable changes
- role jurisdiction confusion recurs
- shipped work repeatedly violates project principles

## Constraints

- Prefer deleting, merging, or clarifying rules over adding rules.
- Every new rule must replace an old rule, retire a recurring failure, or be time-boxed as an experiment.
- Process changes must be small, reversible, and evaluated.
- Meta Loop changes require a changelog entry.
- Do not add bureaucracy to handle a one-off mistake.

## Meta Loop output

A Meta Loop run writes:

- evidence summary
- proposed process change
- rule added/changed/removed
- expected benefit
- evaluation date or trigger
- rollback condition
