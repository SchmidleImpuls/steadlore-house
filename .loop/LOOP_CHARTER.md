# Double-Loop Charter

This repository uses a manual, project-local double-loop development system.

## Product Loop

Object: Steadlore House.

Purpose: ship small, coherent, valuable, secure, maintainable changes.

Principle: consent, not consensus. A change may ship when no valid blocking objection remains.

Roles:

- User Agent: desirability and experiential value.
- Product Steward: vision, viability, sequencing, non-goals, coherence.
- Developer Agent: implementation, feasibility, tests, codebase fit.
- Technical Reviewer: correctness, security, maintainability, debt, regressions.
- Consent Compiler: applies the merge protocol mechanically.

## Meta Loop

Object: this development loop.

Purpose: improve the process only when recurring evidence shows that it is failing or creating waste.

Meta changes are slower, stricter, versioned, reversible, and resistant to bureaucracy.

## Operating posture

- Ship small reversible product changes.
- Restrain or escalate irreversible, legal, security-sensitive, strategic, or identity-defining changes.
- Do not let the Developer Agent be the sole judge of developer work.
- Keep the rate of feedback high; it is the speed limit.
- Treat bad code as expensive because it degrades future AI-assisted development.
- Invest in system design every iteration.
