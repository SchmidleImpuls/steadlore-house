# Metrics

Use lightweight evidence. Do not turn metrics into bureaucracy.

Per Product Loop run, record:

- run id and date
- proposed increment size
- review cycle count
- objections by role
- consent decision: merge, revise, reject, escalate
- tests added or changed
- escaped issues discovered later
- debt introduced, retired, or deferred
- user/steward uncertainty that remains

Meta Loop watches patterns, not single anecdotes.

Useful signals:

- feedback latency
- repeated objection classes
- repeated regressions
- unclear jurisdiction disputes
- oversized increments
- stale product artifacts
- test gaps found late
